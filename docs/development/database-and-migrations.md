# Database and Migrations

The local PostgreSQL initialization script receives database names, owners, and passwords through explicit Compose environment mappings. It creates six logical databases with distinct owners and never grants cross-service access.

Files in `/docker-entrypoint-initdb.d` run only when PostgreSQL initializes a new `postgres_data` volume. Changing `.env` later does not update an existing volume. Apply deliberate migrations/role changes for an existing database; do not delete a user's volume automatically. Core owns additive migrations `001_core_vertical_slice.sql` through `006_core_payment_recovery_claims.sql`; Food owns `001_food_vertical_slice.sql` through `005_food_idempotency_eligibility.sql`. Run `scripts/migrate.ps1 .env.example` or `scripts/migrate.sh .env.example`, then the corresponding seed helper; the first argument is an optional env-file path. Neither script deletes volumes or resets data. Food Compose runs against PostgreSQL when `FOOD_PERSISTENCE=postgres`. Core application tests use an in-memory adapter for speed, while explicit PostgreSQL persistence tests are available through `CORE_TEST_DATABASE_URL`.
