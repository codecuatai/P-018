# Testing Strategy

Unit tests cover application/domain code; config tests prove fail-fast process settings; API tests cover health/validation; contract tests cover versioned provider/consumer behavior; integration/E2E tests live under root `tests/`; agent evaluations cover intent/slots/tool selection and native/fallback structured-output safety. Default tests use fake LLMs and never call Gemini or a live payment/domain system. The separate live smoke is limited to 3–5 public chat calls and reports configured-key/provider/schema status without exposing secrets.

Before a PR, run environment validation, Compose config, Python lint/pytest and package/import checks for changed services, gateway lint/test/build, and web build when affected. Add deterministic tests with every behavior, config, contract, or migration change. For this audit, Agent recorded `29 passed`, Gateway recorded `18 passed/3 skipped`, and Food recorded `21 passed/3 skipped`. PostgreSQL suites were explicitly skipped because disposable database URLs were not configured; the external E2E run timed out during its restart/environment path. Live Gemini evidence is limited to the five-call smoke recorded in `job.txt`.
