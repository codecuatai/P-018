Core owns confirmations, sandbox payments, refunds, receipts, conversations, saved addresses, idempotency evidence, reconciliation metadata, audit records, durable Assistant action execution receipts, durable multi-service workflow plans, and Phase 1 identity/session evidence. Run `001_core_vertical_slice.sql` through `011_core_multi_service_workflows.sql` against `xone_core`. Migration `005` adds durable provider transactions and saga fields; migration `006` adds atomic payment-recovery claims and refund recovery scheduling; migration `007` stores one safe public Assistant response per consumed actor/conversation/action; migration `008` adds retryable failure state and a bounded processing lease without editing 007; migration `009` adds Core-owned users, Argon2id credential storage, rotating refresh-session evidence and one-time password-reset hashes; migration `010` adds personal context; migration `011` persists multi-service plans and step idempotency evidence. Migrations are additive and owned by the Gateway; they do not access Food tables.

Both `scripts/migrate.sh` and `scripts/migrate.ps1` apply the same ordered Core/Food migration set. Run `python scripts/check-migration-parity.py` to detect drift before changing either script.
